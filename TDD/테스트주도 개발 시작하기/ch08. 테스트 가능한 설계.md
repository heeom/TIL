## 테스트가 어려운 코드

- 하드코딩
- 의존 객체 직접 생성
- 정적 메서드 사용
- 실행시점에 달라지는 결과 → 테스트를 실행하는 시점에 따라 테스트 결과가 달라질 수 있다
    - 메서드 내부에서 LocalDate.now() 사용하는 경우
    - Random을 이용해서 임의 값을 사용하는 코드
- 역할이 섞여 있는 코드
- 메서드 중간에 소켓 통신 코드가 포함되어 있는 경우
- 콘솔에서 입력을 받거나 결과를 콘솔에 출력하는 경우
- 테스트 대상이 사용하는 의존대상 클래스나 메서드가 final → 대역으로 대체가 어려울 수 있다.
- 테스트 대상의 소스를 소유하고 있지 않아서 수정이 어려운 경우

→ 의존하는 코드를 교체할 수 있는 수단이 없는것이 문제

## 테스트 가능한 설계

- 하드코딩된 상수 → 생성자나 메서드 파라미터로 받기
- 의존객체 직접 생성 → 의존 대상을 주입받기
    - 의존 대상은 주입받을 수 있는 수단(생성자나 세터)을 제공해서 교체할 수 있도록 한다.
    - 의존 대상을 교체할 수 있게 되면 실제구현 대신에 대역을 사용할 수 있어 테스트를 보다 원활하게 작성할 수 있다.
- 역할이 섞여있는 코드 → 테스트하고 싶은 코드를 분리하기
- 시간이나 임의 값 생성 기능 분리하기
    - 분리한 타입을 사용해서 대역으로 처리
- 외부 라이브러리는 직접사용하지 말고 감싸서 사용하기
    - 외부라이브러리와 연동하기 위한 타입을 따로 만든다.
    - 테스트 대상 코드는 새로 분리한 타입을 사용함으로 써 외부 연동이 필요한 기능을 쉽게 대역으로 대체할 수 있다.

  ```java
  public class AuthService {

    private String authKey = "somekey";
  
    public int authenticate(String id, String pw) {
           boolean authorized = AuthUtil.authorize(authKey);
           if (authorized) {
              return AuthUtil.authenticate(id, pw);
           } else {
              return -1;
           }
     }
  }
  ```
    ``` java
  public class LoginService {
     private AuthService authService = new AuthService);
  ...생략
     public void setAuthService(AuthService authService) {
          this.authService = authService;

 ```
    - AuthService를 대역으로 대체할 수 있게되었으므로 인증 성공상황과 실패 상황에 대해 LoginService가 올바르게 동작하는지 검증할 수 있다.
    - 의존하는 대상이 Final 클래스이거나 의존 대상의 호출 메서드가 final이어서 대역으로 재정의 할 수 없는 경우에도 동일한 기법을 적용해서 테스트 가능하게 만들 수 있다.
