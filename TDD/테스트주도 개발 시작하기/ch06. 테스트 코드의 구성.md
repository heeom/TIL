## 기능에서의 상황

- 기능은 주어진 상황에 따라 다르게 동작한다
    - 파일에서 숫자를 읽어와 숫자의 합을 구한다.
    - 한줄마다 한 개의 숫자를 포함한다

```java
File data = new File("data.txt");
Long sum = MathUtils.sum(data);
```

- 먼저 고려해야 할것
    - File이 없는 상황 처리 → 예외를 발생하거나 문제상황이라는걸 알려줘야 함
- 실행 결과에 영향을 줄 수 있는 상황을 먼저 찾아야 한다.

## 테스트 코드의 구성요소

### 상황, 실행, 결과 확인

- 어떤 상황이 주어지고, 그 상황에서 기능을 실행하고, 실행한 결과를 확인 하는 3가지가 테스트 코드의 기본 골격을 이루게 된다. (given, when, then)
- 근데 상황이 없는 경우도 있음
    - 암호 강도기 측정 예시 같은 경우 실행 결과에 영향을 주는 상황이 없다.

## 외부 상황과 외부 결과

- 상황에는 **외부 요인**도 있다.

```java
File data = new File("data.txt");
Long sum = MathUtils.sum(data);
```

- 파일이 존재하지 않는 경우도 결과를 확인해야 한다.
- 파일이 존재하지 않는 상황은 어떻게 만드는가?
    - 명시적으로 파일이 없는 상황을 만들면 된다.

### 외부 상태가 테스트 결과에 영향을 주지 않게 하기

- 중복 데이터 체크의 경우 DB 데이터 존재 여부에 따라 테스트 실행 결과가 달라진다.
- 실행 전에 외부를 원하는 상태로 만들거나 테스트 실행 후에 외부 상태를 원래대로 되돌려 놓아야 한다.
    - 테스트 코드 실행 후 데이터 제거
- 테스트코드에서 다루기 어려운 외부상태가 존재하기도 한다.
    - 테스트 대상의 상황과 결과에 외부 요인이 관여할 경우 **대역**을 사용하면 테스트 작성이 쉬워진다.
        - 외부요인 : 외부 API와 통신해야 하는 경우
    - **대역**은 **테스트 대상이 의존하는 대상의 실제 구현을 대신하는 구현인데** 이 대역을 통해서 외부 상황이나 결과를 대체할 수 있다.
