## 기본생성자에 대하여...
개발을 하다가 어떤 경우는 클래스에 기본생성자가 필요하다고 에러가 나는데, 어떤 경우는 기본생성자 없이도 잘 동작하는걸 본 경험이 있을 것이다.
Spring Boot, JPA, Jackson 등을 사용하다 보면 어떤 경우엔 기본 생성자가 필수이고, 또 어떤 경우엔 없어도 무방한 경우가 있다. 
기본적이지만 늘 헷갈렸던 부분을 이참에 글로 한번 정리해보려고 한다..
다음 3가지 케이스에서 기본 생성자의 필요 여부와 이유를 알아보자.

  - Jackson으로 JSON을 파싱할 때 기본 생성자가 꼭 필요한 이유는?
  - JPA Entity에는 기본 생성자가 왜 필수일까?
  - Spring MVC에서 @RequestBody와 @ModelAttribute 사용 시 기본 생성자는 어느 상황에서 필요할까?


## Jackson을 사용한 Deserialize시 기본생성자는 왜 필수일까?

Jackson을 사용한 역직렬화시 기본생성자가 없다면 예외가 발생한다. 보통 Response DTO에 기본생성자를 작성하지 않아서, 에러가 발생하는 일이 잦다. 

진짜 에러가 발생하는지 예제로 확인해보자

```java
public class DeserializationTest {

    private ObjectMapper objectMapper;
    private final String message = "{\"key\": \"value\"}";

    @BeforeEach
    public void init() {
        objectMapper = new ObjectMapper();
    }

    @Test
    @DisplayName("역직렬화 대상 클래스에 기본생성자가 존재하지 않으면 역직렬화시 예외가 발생한다")
    public void notExistsNoArgsConstructorThenThrowException() {
        Assertions.assertThrows(JsonProcessingException.class, () -> objectMapper.readValue(message, Message.class));
    }

    static class Message {
        private String key;
    }
}
```

### Jackson으로 역직렬화 시 왜 기본생성자가 필수일까?

- Jackson은 기본 생성자를 통해 객체를 생성한 후, setter 방식 또는 field access 방식으로 값을 주입한다.
- 그러므로 클래스에 명시적인 기본생성자가 없으면 역직렬화에 실패한다.

### 역직렬화 과정을 살펴보면

1. 기본생성자로 인스턴스를 생성한다.
    - 리플렉션으로 객체를 생성하는데 이때 기본생성자가 반드시 필요하다.
2. 필드 접근이나 setter 메서드를 통해 값을 주입한다.
    - setter가 존재하면
    
    ```java
    Method setter = clazz.getMethod("setName", String.class);
    setter.invoke(obj, "Zoey");
    ```
    
    - setter가 없다면, field 접근을 통해 값을 주입
    
    ```java
    Field field = clazz.getDeclaredField("name");
    field.setAccessible(true);
    field.set(obj, "Zoey");
    ```
    

정리하면 역직렬화시 객체를 생성하는 방식은 기본생성자 + 리플렉션을 기본으로 사용한다. 이때, 값을 주입하는 방식은 setter 또는 필드 접근 방식을 사용한다. 그래서 setter는 optional이지만 기본생성자는 필수 조건이다.

- 값 주입 방식은 setter가 우선적으로 사용되지만, setter가 없고 private 필드인 경우는 reflection + setAccessible(true) 필드 접근 방식을 사용한다.

### ⚠️ @JsonCreator + @JsonProperty 를 사용하면 final 필드도 생성자 기반 역직렬화가 가능하다

```java
		@Test
    @DisplayName("기본생성자 없이 생성자 기반 역직렬화를 사용하면 예외 발생하지 않는다")
    public void deserializeWithJsonCreator() throws JsonProcessingException {
        Example result = objectMapper.readValue(message, Example.class);
        Assertions.assertEquals("value", result.getKey());
    }

    static class Example {
        private final String key;

        @JsonCreator
        public Example(@JsonProperty("key") String key) {
            this.key = key;
        }

        public String getKey() {
            return key;
        }
    }
```

- Jackson은 final 필드를 다루기 위해 생성자 또는 JsonCreator 기반 주입 방식을 제공한다.
    - 생성자 호출 시 필드 초기화 가능하므로 final 필드도 역직렬화가 가능하다.
