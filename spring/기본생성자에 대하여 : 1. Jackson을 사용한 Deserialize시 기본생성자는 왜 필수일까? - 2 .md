어제 코드를 작성하다가 Json 구조가 복잡해서 static inner class 한군데에 기본생성자를 명시하는걸 깜빡하고 빠트렸다. 그런데 역직렬화에 성공하는 게 아닌가?

그때 상황을 간단하게 재현해서 여러가지 케이스를 좀 더 테스트 해봤다.

*java 17, spring boot 3.4.4 기준*

```java
@Getter
public class TestData {

    @JsonProperty("param1")
    private String param1;

    public String param2;
}

@Test
@DisplayName("역직렬화 테스트")
public void deserializeWithNoArgsConstructorThenSuccess() throws JsonProcessingException {
    TestData testData = objectMapper.readValue(message, TestData.class);
}
```

테스트 결과는 다음과 같다.

```java
 * 1. 다른 생성자가 없을 때 NoArgsConstructor 명시는 필수가 아님 -> 컴파일시 java가 자동 생성 해준다
 *
 * *** private 필드 기준
 * 2. @Getter (o) + @JsonProperty (x) -> 역직렬화 성공
 * 3. @Getter (x) + @JsonProperty (o) -> 역직렬화 성공
 * 4. @Getter (o) + @JsonProperty (o) -> 역직렬화 성공
 * 5. @Getter (x) + @JsonProperty (x) -> 역직렬화 실패
 *    - com.fasterxml.jackson.databind.exc.UnrecognizedPropertyException: Unrecognized field "key" (class com.example.springboottest.data.TestData), not marked as ignorable (0 known properties: ])
 *
 * *** public 필드 기준
 * 6. @Getter (x) + @JsonProperty (x) -> 역직렬화 성공

```

하나씩 살펴보자.

### 1. NoArgsConstructor 명시는 필수가 아니다.
   - 기본 생성자가 명시돼 있지 않아도 명시적으로 생성자를 하나도 정의하지 않은 경우, javac가 자동으로 기본 생성자를 생성한다.
   - 리플렉션으로 객체 생성시에 자동으로 생성된 기본생성자를 사용하면 역직렬화가 가능하다.
### 2. private 필드 기준
   - Jackson은 기본적으로 다음과 같은 순서로 필드 매핑을 시도한다.
      - @JsonCreator가 붙은 생성자
      - setter
      - 리플렉션으로 필드 직접 접근
      - Java Bean 규칙에 따라 getter/setter에 @JsonProperty가 붙은 경우
   - 3, 4번은 `@JsonProperty` 를 통해 필드 매핑(필드명 기반)을 강제하고, private 필드여도 리플렉션을 통해 값 주입이 가능하므로 역직렬화가 성공한다.
   - 5번 테스트 결과 private 필드는 Jackson이 기본적으로 접근하지만, ObjectMapper 설정이 FAIL_ON_UNKNOWN_PROPERTIES = true 이면, 필드가 무시되면서`com.fasterxml.jackson.databind.exc.UnrecognizedPropertyException` 예외가 발생한다.
      - `@JsonIgnoreProperties(ignoreUnknown = true)` 을 클래스 레벨에 추가하면 → JSON에 정의된 필드가 Java 클래스에 없더라도 역직렬화 시 예외를 발생시키지 않고, 무시하도록 할 수 있다. → 마이크로서비스 간 통신에서 버전이 달라 JSON 구조가 일부 달라지는 상황 또는 외부 서비스와 통신하는 경우 유용하다.
   - 그런데 `@Getter` 는 역직렬화와는 관련이 없다고 알고 있는데, 왜 getter의 유무에 따라 2,5번 테스트 결과가 달라졌을까?

       ```java
       @Getter
       private String param1;
       
       - Jackson은 getter가 존재하므로 이를 통해 직렬화는 당연히 가능
       - 역직렬화의 경우에도 Jackson은 getParam1()이 있는 걸 보고, Java Bean 속성 param1이 존재한다고 인식함
       - 그리고 해당 이름이 JSON의 "param1"과 일치하므로 필드에 값을 주입
       ```

      - getter 가 만들어준 public getter 메서드가 jackson의 내부 프로퍼티 추론에 영향을 줬기 때문이다.
      - 즉 Jackson의 필드 인식 여부에 따라 역직렬화 성공여부가 달라진것이다.
### 3. public 필드 기준
   - @Getter (x) + @JsonProperty (x) → 역직렬화 성공
   - public 필드는 Jackson이 기본적으로 인식하여 접근 가능하므로 역직렬화 성공한다.
